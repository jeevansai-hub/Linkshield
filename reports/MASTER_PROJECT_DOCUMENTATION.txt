1. EXECUTIVE SUMMARY & PROBLEM STATEMENT
================================================================================
Phishing links, drive-by malware downloads, and malicious URL distribution 
represent major cyber threat vectors in modern network security. Traditional 
security techniques relying on static domain blacklists (such as Google Safe 
Browsing or DNS blocklists) suffer from zero-day vulnerability windows—failing 
to detect newly registered or dynamically generated phishing URLs before the 
domain is reported and blacklisted.

LinkShield addresses this critical vulnerability by deploying an inline, 
lightweight Machine Learning classifier that evaluates raw URLs in real-time 
(<50ms latency target) using static lexical, host, and structural feature 
analysis.

Core Problem:
Can an inline machine learning model classify a URL as Safe-Looking (0) or 
Suspicious (1) using ONLY in-memory string-level structural characteristics, 
without accessing the destination website or initiating network connections?

Solution Overview:
LinkShield extracts 16 static numerical features directly from raw URL strings 
(length, subdomain count, special character density, IP host match, HTTPS scheme, 
lure keywords) and feeds them into a trained Random Forest / Logistic Regression 
classifier. The model outputs a continuous risk probability score P(Suspicious) 
and classifies the URL in 7.24 milliseconds on average, guaranteeing zero 
destination website access.

3. ZERO-TRUST SECURITY & SAFETY PRINCIPLES
================================================================================
CRITICAL SECURITY DIRECTIVE:
Under no circumstances shall LinkShield code, workflows, or web applications 
issue live network connections to URLs being analyzed.

Prohibited Operations:
1. NO HTTP GET / POST / HEAD requests to target URLs.
2. NO DNS resolution lookups (socket.gethostbyname, nslookup).
3. NO HTTP redirect following.
4. NO web scraping or DOM rendering.
5. NO dynamic JavaScript / payload execution.

Rationale:
Issuing live network requests to malicious URLs can:
- Trigger drive-by malware exploits on the scanner host.
- Alert threat actors that their phishing link is being audited (enabling evasive URL cloaking).
- Leak scanner IP address and metadata to malicious infrastructure.

LinkShield's URLLexicalFeatureExtractor operates 100% in-memory using standard 
Python string operations (urllib.parse, Regular Expressions).

LinkShield implements a dual-experiment architecture:

EXPERIMENT A (UCI Baseline):

- Purpose: Establishes a realistic benchmark on noisy real-world data.

EXPERIMENT B (LinkShield Raw URL Engine):
- Source: Raw URL feeds (600 safe Alexa/Tranco domains + 600 PhishTank phishing URLs).
- Samples: 1,200 rows of raw URL strings.
- Target Mapping: 0 = Safe-Looking, 1 = Suspicious.
- Class Balance: Exactly 50.0% Safe / 50.0% Suspicious.

Splitting Strategy:
- 80% Training Set (960 samples)
- 10% Validation Set (120 samples)
- 10% Final Test Set (120 samples)
- Stratification: Enforced stratify=y with random_state=42.

5. STATIC FEATURE EXTRACTION ENGINE (16 FEATURES)
================================================================================
Implemented in src/features/extract_features.py, the URLLexicalFeatureExtractor 
parses raw URL strings into a 16-element numerical vector:

1. url_length               : Total character count of full URL string.
2. domain_length            : Character length of extracted netloc/hostname.
3. path_length              : Character length of URL path component.
4. query_length             : Character length of query string.
5. num_dots                 : Count of '.' characters in URL string.
6. num_hyphens              : Count of '-' characters in hostname.
7. num_underscores          : Count of '_' characters in URL string.
8. num_slashes              : Count of '/' characters in URL string.
9. num_question_marks       : Count of '?' characters in URL string.
10. num_equal_signs         : Count of '=' characters in URL string.
11. num_digits              : Count of numeric characters (0-9) in URL.
12. digit_ratio             : Ratio of num_digits / url_length.
13. num_special_chars       : Count of non-alphanumeric special characters.
14. num_subdomains          : Count of subdomains in hostname.
15. path_depth              : Count of path slash hierarchy levels.
16. has_ip                  : RegEx binary flag (1 if hostname is IPv4/v6 address).
17. has_https               : Binary flag (1 if scheme is https).
18. has_shortener_domain    : Binary flag (1 if hostname matches known shortener).
19. suspicious_keyword_count: Count of security lure terms (login, bank, verify, etc.).

6. MACHINE LEARNING MODEL PIPELINES
================================================================================
Implemented in src/models/train_evaluate.py, the ModelPipeline class provides 
reproducible model training with random seed 42:

1. Model 1 — Logistic Regression Baseline:
   - Architecture: Pipeline([('scaler', StandardScaler()), ('classifier', LogisticRegression(C=1.0, max_iter=1000, random_state=42))])
   - Scaling Rule: StandardScaler is fitted strictly on X_train inside the pipeline to prevent data leakage.
   - Purpose: Establishes a fast, linear, interpretable baseline.

2. Model 2 — Random Forest Classifier:
   - Architecture: RandomForestClassifier(n_estimators=100, max_depth=15, random_state=42)
   - Scaling Rule: Operates directly on raw unscaled numerical features (decision trees are scale-invariant).
   - Purpose: Captures complex non-linear feature interactions without feature scaling.

7. THE 5 MANDATORY EVALUATION METRICS & JUSTIFICATIONS
================================================================================
In threat classification, relying solely on Accuracy is dangerously misleading 
because malicious URLs represent an imbalanced fraction of web traffic, and 
false negatives (missing a malicious URL) have catastrophic security consequences.

1. Accuracy: (TP + TN) / (TP + TN + FP + FN)
   Measures overall correctness across all predictions.

2. Precision: TP / (TP + FP)
   Measures how many flagged URLs are genuinely suspicious. High precision 
   minimizes false alarms (False Positives), preserving user trust.

3. Recall (Sensitivity / Detection Rate): TP / (TP + FN)
   CRITICAL METRIC FOR LINKSHIELD. Measures the proportion of actual malicious 
   URLs successfully caught. High recall minimizes False Negatives (uncaught attacks).

4. F1-Score: 2 * (Precision * Recall) / (Precision + Recall)
   Harmonic mean of Precision and Recall, providing a single balanced operational score.

5. ROC-AUC: Area under the ROC curve (True Positive Rate vs False Positive Rate).
   Evaluates the model's intrinsic discrimination power across all possible 
   decision thresholds, independent of class distribution.

10. SCIENTIFIC SANITY AUDIT & METHODOLOGICAL DISCLOSURES
================================================================================
A 20-point scientific audit was conducted on the 1.0000 Experiment B results:

Audit Findings:
1. Zero Code Data Leakage: Feature extraction operates strictly on URL strings 
   with zero access to target labels. Scalers are fitted strictly on X_train.
2. High Feature Separability: Static features exhibit high correlation with 
   target labels on template data (num_special_chars r=0.9079, url_length r=0.8951).
3. URL Template Overlap in Synthetic Dataset: raw_urls_dataset.csv contains 
   1,200 rows sampled from 25 template domain/host pools (301 unique URLs). 
   Random splitting created 85 duplicate URL strings between Train and Test splits.

Scientific Conclusion:
LinkShield achieved 100% test-set performance on the controlled template-based 
dataset; however, the scientific audit identified substantial URL-level overlap 
across splits and strong feature separability. Therefore, this result demonstrates 
successful classification of the constructed dataset rather than evidence of 
100% real-world phishing detection. Experiment A (UCI Baseline: 85.83% Accuracy, 
0.9391 ROC-AUC) serves as our realistic benchmark.

13. COMPREHENSIVE HOW-TO-RUN GUIDE
================================================================================
Step 1: Clone Repository & Open Folder
  git clone https://github.com/jeevansai-hub/Linkshield.git
  cd Linkshield

Step 2: Set Up Virtual Environment & Install Dependencies
  python -m venv venv
  # On Windows PowerShell:
  venv\Scripts\activate
  # On Linux / macOS:
  source venv/bin/activate

  pip install --upgrade pip
  pip install -r requirements.txt

Step 3: Run Automated Unit Tests
  python -m unittest discover -s tests -p "test_*.py"

Step 4: Launch Real-Time Streamlit Web App
  python -m streamlit run app.py

Step 5: Run Single-Line CLI Prediction
  python -c "import joblib, pandas as pd; from src.features.extract_features import URLLexicalFeatureExtractor; ext = URLLexicalFeatureExtractor(); models = joblib.load('models/linkshield_models.joblib'); res = models['engine_rf'].predict_proba(pd.DataFrame([ext.extract('http://login.paypal.account-verify.com/update?id=123')])[models['feature_names']])[0]; print('Probability Suspicious:', round(float(res)*100, 2), '%'); print('Label:', 'SUSPICIOUS' if res >= 0.30 else 'SAFE-LOOKING')"
